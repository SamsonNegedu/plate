# Plate

Single-user, offline-first PWA for logging calories by barcode. React 19 + TypeScript + Vite client, Go + SQLite server, one static binary serving the API and the built SPA.

Start with `.claude/tasks/README.md`, then the current phase file. Locked decisions live in `.claude/tasks/00-architecture.md`. `mockups.html` is the approved visual direction.

## Non-negotiables

- The client is offline-first: Dexie is the local source of truth, the server is authoritative for sync order.
- Every entry stores a nutrition snapshot. Later food changes never rewrite history.
- Missing nutrients are `NULL`, never `0`. A food without kcal is not loggable.
- Never treat a per-serving value as per-100 g. Normalize or mark it missing.
- IDs are UUIDv7 generated by the client for entries. Sync ops are idempotent by `op_id`.
- Deletes are tombstones. No hard deletes of syncable rows.
- The browser never calls Open Food Facts directly. All food and image traffic goes through the Go server.
- The catalog seed is built from OFF and includes nutrition. A catalog hit must not call OFF; OFF is the long-tail and refresh fallback.
- The mockups are the design floor. Match or exceed them; a downgrade requires updating the mockup first and an explicit decision.
- No analytics, no trackers, no third-party runtime services.
- Camera requires HTTPS. Localhost is the only exception.
- HTTPS comes from a proxy or tunnel you run in front. The app publishes no port, and the app session is the only auth gate: the app never trusts forwarded identity or IP headers.
- One binary, one SQLite file, no external queue or cache.

## Stack

| Concern | Choice |
|---|---|
| Client | React 19, TypeScript strict, Vite, React Router 7 |
| Local data | Dexie 4 + `dexie-react-hooks` |
| UI state | Zustand (ephemeral only) |
| Forms | React Hook Form + Zod |
| Components | Radix UI + Tailwind CSS v4 |
| Charts | Recharts |
| Local search | MiniSearch |
| Barcode | native `BarcodeDetector` + `barcode-detector`/`zxing-wasm` |
| PWA | `vite-plugin-pwa` 2 (injectManifest) + Workbox 7 |
| Server | Go, `net/http`, chi, Huma v2 |
| Database | SQLite via `modernc.org/sqlite`, WAL, FTS5 |
| Local catalog | Self-built OFF German seed with nutrition (ODbL) |
| Queries | sqlc |
| Migrations | goose v3 |
| Auth | `alexedwards/scs/v2` + Argon2id |
| Deploy | Docker Compose, SQLite snapshot backups |

## How to work

1. Read `.claude/tasks/README.md`, `00-architecture.md`, and the phase you are on.
2. Load the relevant guardrail skill before editing: Go → `golang-code-style`, React → `react-pwa`, tests → `testing`, entries/sync → `sync-integrity`, auth → `security`, UI/charts → `ui-design-system`.
3. Implement one phase only. Do not pull later-phase features forward.
4. Update the phase status and the README progress tracker as you go.
5. Run `make verify` before calling a phase done.
6. Pause for review after Phases 0, 4, 6, 9, and 12. Do not start the next phase while a High-impact unknown or a P1/P2 bug is open.
7. If a locked decision changes, edit `00-architecture.md` first, then the affected phases. Do not silently diverge.

## Code standards

- Comments: one line, only for a non-obvious why. No comment that restates the code.
- Go errors: wrap with context (`fmt.Errorf("...: %w", err)`), map to typed domain errors at boundaries, never panic for expected failures.
- TypeScript: `strict: true`. No `any`, no non-null assertions on external data, no `@ts-ignore` without a one-line reason.
- Validate at boundaries (HTTP, forms, external APIs). Do not add defensive branches for states the producing code cannot create.
- Every behavior gets a test at the lowest useful layer. Sync, auth, nutrition math, and migrations get integration tests.
- Generated files are never hand-edited: sqlc output, OpenAPI types, icons, lockfiles.
- UI follows the tokens and type scale in `mockups.html`. No new colors, fonts, or spacing systems.
- New dependencies need a one-line justification in the phase file. Do not add one because it is familiar.

## Forbidden without a written decision

- ORM (GORM, ent), Gin/Echo/Fiber, a second database, Redis, a queue.
- TanStack Query, Redux, MobX, or persisted app data in `localStorage`.
- CSS Modules, styled-components, or a second styling system. Tailwind v4 with the token theme is the only one.
- Runtime CDN scripts, fonts, or WASM. Everything is self-hosted.
- SSR, a native wrapper, multi-user accounts, sharing, or social features.
- Hand-written OpenAPI or hand-written row scanning.
- Hard deletes for entries, foods, settings, saved meals, or favorites.
- Storing missing nutrition as `0`.
- Calling OFF from the browser.

## Definition of done

- `make verify` passes.
- The phase acceptance checklist is complete.
- New behavior is covered by tests.
- OpenAPI and generated TypeScript types are in sync.
- Works at 400 px, keyboard-only, reduced motion, light and dark.
- No P1/P2 defects.
- The README tracker and phase status are updated.
- The design parity matrix in `.claude/tasks/design-parity.md` is satisfied; no unresolved P1/P2 design regression.
- Docs and attribution are updated when a data source or license changes.
